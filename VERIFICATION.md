## Build 53: iOS 17 Live Activity contrast and controls

`ecad0ca` changes only Live Activity presentation/intent configuration, related verification and build numbering. The shipped build 52 metadata declared `RouteActivityIntent` introduced in iOS 17.2 and had an empty legacy `mangledTypeName` in both app and widget, despite the source annotation specifying 17.0. Apple's [documented deployment-processing workaround](https://developer.apple.com/documentation/xcode-release-notes/xcode-15_3-release-notes), `ENABLE_APPINTENTS_DEPLOYMENT_AWARE_PROCESSING=NO`, makes both packaged declarations say 17.0 and supply the legacy type lookup. Packaging now asserts this, and unused Stop-request/choice parameters are optional. Execution still uses the single app-process runtime, awaits its update, and requires no new entitlements.

The card now resolves explicit background, text, accent and button colors together from SwiftUI appearance, avoiding an independently archived UIKit system background. Light appearance uses dark text on pale surfaces; dark appearance uses white text on charcoal/purple surfaces. Dynamic Island explicitly uses the dark palette in either appearance. No route movement, injection or speed/course behavior changed.

[CI run](https://github.com/dm2mymcszt-commits/TrollRoute/actions/runs/36176183025), [signed package](https://github.com/dm2mymcszt-commits/TrollRoute/actions/runs/36176183025/artifacts/10882880701). ## Build 52: startup import lockout hotfix

User testing reported a blocking import/preferences-save error after removing the old app. `0b283c9` changes only startup/import behavior and the build number. Legacy discovery now trusts current installed status instead of a potentially stale bundle URL, and stops before inspecting leftover containers when the old app is absent. The migration engine likewise skips absent installations without reading sources, replaying its journal, or requiring a preferences flush. Completed, acknowledged and explicitly skipped imports bypass discovery; existing data is not cleared. An optional-import error always offers Continue to TrollRoute, even when saving the opt-out fails. The underlying device-specific reason for the preferences flush failure is not established; the fix removes its ability to lock the user out.

[Build 52 CI](https://github.com/dm2mymcszt-commits/TrollRoute/actions/runs/36126233477) passed the complete package job, including migration tests that inject a preferences-save failure followed by uninstall, stale/unreadable sources and current Favorites, preservation of existing preferences/journal, acknowledged imports with a missing completion flag, and explicit skip. The downloaded [package](https://github.com/dm2mymcszt-commits/TrollRoute/actions/runs/36126233477/artifacts/10860531967) independently passes identity and app/share/widget signing checks; SHA-256 `942e21bffc3e426869063bd1a5eb704b365ce0143e27895d473edc489732c3ee`.

Attempt 1 passed package/model checks, route-session UI, Live Activity UI and icon checks. Sharing UI timed out waiting five seconds for the simulator's background state before enqueueing the test request; map UI had an unexpected test-runner exit during `testSaveSearchAndMapPinWithoutSelectingLocation`. Both jobs passed on attempt 2 with unchanged code and tests; all six CI jobs are now successful. No unrelated production or test behavior was modified, and no fix for those simulator failures is claimed.
